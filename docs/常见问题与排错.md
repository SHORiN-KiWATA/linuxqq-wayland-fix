# 常见问题与排错

## 已知问题

### 使用 Easy Effects 时，QQ 一开通话/共享就崩

Easy Effects 会把新出现的音频流移到它自己的设备上，这会触发 QQ 音频模块里的竞态 bug。解决：

- Easy Effects →「输入」和「输出」页 → 排除的应用 → 都加上 **`TRAE`**（QQ 音频流的应用名）；
- QQ「设置 → 音视频通话」里把麦克风选成 **Easy Effects Source**，麦克风照样经过 Easy Effects 处理。

在界面里加好后，配置文件（`~/.config/easyeffects/db/easyeffectsrc`，flatpak 版在 `~/.var/app/com.github.wwmm.easyeffects/config/easyeffects/db/`）的 `[StreamInputs]`、`[StreamOutputs]` 两节里应该都有 `blocklist=…TRAE…`。`--doctor` 会检查这一点，也会指出 Easy Effects 不认的写法（如 `exclude=`）。

### 不要同时运行其它剪贴板同步工具

本工具已经在 QQ 内部双向同步剪贴板，再运行 linuxqq-clipsync 之类的 X11↔Wayland 同步工具会重复同步。`--doctor` 会检查 linuxqq-clipsync。

### KDE 下剪贴板修复默认禁用

KDE Plasma（KWin）自己会把 XWayland 的剪贴板与 Wayland 双向同步（KWin/Klipper），QQ 的 X11 剪贴板本来就能和 Wayland 程序互通。再叠加本工具的剪贴板桥会互相抢所有权、来回循环，实测会导致 QQ 崩溃。所以 **KDE 会话下默认不加载 `libqq-clipbridge.so`**（启动日志头部会写 `clipboard=off(kde)`），QQ 的复制粘贴走 Plasma 自带同步即可。

想强制启用（仅排查问题用，可能崩）：`QQ_CLIPBOARD_FIX_FORCE=1 linuxqq-wayland-fix`。

### 截图窗口在全屏下的行为

QQ 的截图窗口是按「放在桌面左上角、和整个桌面一样大」设计的。本工具做了三件事让它变得可用：

- `libqq-screenshot.so` 把 QQ 看到的「屏幕尺寸」报成当前聚焦显示器（优先 niri 的聚焦输出，其它合成器退回指针位置），只截那一块——所以截图内容是单屏的，不再把所有显示器拼在一起；
- `libqq-borderfix.so` 在协议层替截图覆盖层补上标题 `QQ 截图` 并请求全屏，平铺式合成器会把它当覆盖层精确铺满当前显示器，而不是平铺成一个普通窗口；
- 因此也可以按标题 `QQ 截图` 写窗口规则，例如 niri：

  ```kdl
  window-rule {
      match app-id="QQ" title="QQ 截图"
      open-fullscreen true
  }
  ```

KDE、GNOME 都不支持 `wlr-screencopy`。KDE（Plasma 6）下本工具改用 KWin 自己的 `ScreenShot2` 接口拿原始像素（通过一个自带权限声明的 helper，见 [原理详解](原理详解.md#kde-截图kwin-screenshot22026-10-03)）；GNOME 下走 `org.freedesktop.portal.Screenshot`（第一次弹 GNOME 自己的截图对话框授权，之后静默，见 [原理详解](原理详解.md#gnome-截图portal-screenshot2026-10-03)）。想对照复现：`QQ_SCREENSHOT_FIX_DISABLE=1`（整个截图修复）、`QQ_SCREENSHOT_KDE=0`（只关 KDE 路径）、`QQ_SCREENSHOT_PORTAL=0`（只关 GNOME portal 路径）、`QQ_BORDER_FIX_DISABLE=1`（标题与全屏）。

### 共享时出现全屏「屏幕共享」边框窗口

Wayland 下 QQ 会把共享指示边框显示成一个真实的全屏窗口，平铺式合成器里会占满一屏。本工具会自动把它隐藏：`libqq-borderfix.so` 在 socket 层解析 QQ 出站的 Wayland 协议，只把标题为「屏幕共享」且尺寸不设限的那张窗口的绘制缓冲摘掉；共享预览和「共享中」工具条不受影响。

原理见 [原理详解](原理详解.md#附共享边框窗口)。

如果仍然出现：确认旧 QQ 已完全退出（含托盘）再从「QQ（Wayland修复版）」启动；正常时日志里应有 `hiding 屏幕共享 border window`。想对照复现可以 `QQ_BORDER_FIX_DISABLE=1 linuxqq-wayland-fix`。

### 弹出「提示」麦克风通知条

进语音等场景下 QQ 会弹出标题为「提示」的窄条通知（例如「正在使用"系统默认（Easy Effects Source）"作为您的麦克风」，实测 1200×64）。本工具会自动把它隐藏：`libqq-borderfix.so` 识别 `app_id == "QQ"`、标题「提示」、宽 ≥400 且高 ≤128 的窗口，在协议层摘掉它的绘制缓冲；更大的同名对话框不受影响。

原理见 [原理详解](原理详解.md#提示条与麦克风通知2026-10-03)。

如果它仍然弹出：确认旧 QQ 已完全退出（含托盘）再从「QQ（Wayland修复版）」启动；正常时日志里应有 `hiding QQ notification window (提示, 1200x64)`。想保留这类提示可以 `QQ_BORDER_FIX_DISABLE=1 linuxqq-wayland-fix`（会同时关掉共享边框隐藏和截图覆盖层标题/全屏）。

### 流畅度

共享画面由 QQ 单线程软件 H.264 编码，帧率由 QQ 自己的策略决定，本项目无法改善。在选择框里选**单个窗口**会更流畅。

### 观看共享时画面花屏（横竖条纹）

现象：用 Wayland 模式观看别人的屏幕共享，画面花成横竖黑线；同一路共享在手机、Windows 上正常，X11 模式、摄像头画面也正常。

原因：QQ 插件用 `GL_LUMINANCE` 纹理上传 I420 视频帧；Wayland 下 ANGLE 走 EGL/GLES 3.0 上下文，而 GLES3 删掉了这个格式，ANGLE 的模拟在 Mesa 上把纹理写坏。详见 [原理详解](原理详解.md#附观看共享花屏)。

处理：

- 启动器默认检测到 Vulkan 时会自动加 `--use-angle=vulkan`，一般不需要手动处理；
- **混合显卡（核显 + 独显）**：只要 NVIDIA 的 Vulkan 设备可用就会触发（Chromium/ANGLE 的多设备问题）。启动器会自动把 QQ 的 Vulkan 限定到显示 GPU；手动等价命令：

  ```bash
  VK_DRIVER_FILES=/usr/share/vulkan/icd.d/radeon_icd.json linuxqq-wayland-fix
  ```

  （文件名换成显示 GPU 的 ICD；显示在 NVIDIA 上的机器则试 `QQ_WAYLAND_FIX_ANGLE=swiftshader` 或 X11。）
- 没有 Vulkan（或加了仍有问题）时，可以：

  ```bash
  QQ_WAYLAND_FIX_ANGLE=swiftshader linuxqq-wayland-fix
  ```

  画面会正常，但换成软件 ANGLE，较慢；
- 也可以直接以 X11 跑 QQ（观看共享正常，但不是原生 Wayland）：

  ```bash
  MESA_SHADER_CACHE_DISABLE=true XDG_SESSION_TYPE=x11 \
  LD_PRELOAD=/usr/lib/linuxqq-wayland-fix/libqq-wl-portal.so:/usr/lib/linuxqq-wayland-fix/libqq-clipbridge.so:/usr/lib/linuxqq-wayland-fix/libqq-screenshot.so \
  /opt/QQ/qq --ozone-platform=x11
  ```

## 排错

先运行自检：

```bash
linuxqq-wayland-fix --doctor
```

它会检查修复是否安装、QQ 更新后修复是否仍然适用、桌面环境是否支持，以及最近的崩溃记录。

AppImage 版（`linuxqq-appimage`）的内部实现检查需要 **QQ 运行中**：`broadcast-core.so`、`wrapper.node` 这些文件在 AppImage 的挂载目录里，`--doctor` 会从运行中主进程的 exe 定位（安装版仍走 `/opt/QQ`）；QQ 没运行时这几项会提示跳过。

### 日志

日志在 `$XDG_RUNTIME_DIR/linuxqq-wayland-fix.log`，每次启动会重新写：

```bash
grep -E 'qq-wl-portal|qq-clipbridge|qq-screenshot|qq-borderfix' "$XDG_RUNTIME_DIR/linuxqq-wayland-fix.log"
```


### 崩溃记录

QQ 崩溃时，Bugly 的崩溃记录（`tomb_*.txt`）会保存到 `~/.cache/linuxqq-wayland-fix/crash/`（原位置会被 `linuxqq` 启动脚本清空），反馈问题时请附上。

### 症状对照

| 症状 | 原因 / 办法 |
| --- | --- |
| 提示「Wayland桌面环境暂时无法使用屏幕分享功能」 | 不是从「QQ（Wayland修复版）」打开的 |
| 点共享没反应，`coredumpctl` 有 QQ 的 SIGTRAP，栈里有 `PulseAudioWrapper` | Easy Effects，见上文 |
| 点「确定」没反应，栈里有 `ZSTD_` / `libgallium` | QQ 自带的 zstd 与 Mesa 冲突；启动器已设置 `MESA_SHADER_CACHE_DISABLE=true`，请确认没被覆盖 |
| 日志里没有任何 `qq-wl-portal` / `qq-clipbridge` | QQ 没被注入（旧 QQ 没退干净），或 QQ 更新后改了实现，运行 `--doctor` |
| `compositor supports neither …` | 合成器不支持 data-control（如 GNOME），剪贴板修复不可用 |
| KDE 下日志头部显示 `clipboard=off(kde)` | 正常：KDE 自带 XWayland 剪贴板同步，本修复默认禁用；QQ 的复制粘贴仍可用 |
| `response=1` | 在 portal 选择框里点了取消 |
| 按截图键 QQ 闪退，日志里有 `X_GetImage` 的 `BadMatch` | 截图修复没有生效（旧 QQ 没退干净，或没从「QQ（Wayland修复版）」打开）；正常时日志里有 `[qq-screenshot] captured …` |
| KDE 下截图背景仍是黑的 | KDE 路径没生效：确认装的是新版本（有 `qq-screenshot-helper` 及其 `.desktop`），日志里应有 `kde: captured workspace …`；没有就运行 `--doctor` 并反馈 |
| GNOME 下第一次截图弹出 GNOME 自己的截图对话框 | 正常：portal 需要首次授权，授权后静默；取消则本次退回黑图 |
| Hyprland（或其它 XWayland 报逻辑尺寸的合成器）截图内容只占左上角四分之一 / 重影 | 缩放输出的尺寸不一致；v0.2.11 起统一上报 Wayland 输出的原生模式尺寸，升级即可 |
| 点截图窗口的 ✓（复制/保存到输入框）后 QQ 闪退，日志里有 `fatalHandler signo: 13` | Wayland 剪贴板数据源的 SIGPIPE 被 Bugly 当致命错误；v0.2.6 起 `libqq-clipbridge.so` 已把 SIGPIPE 设为忽略，升级即可 |
| 点「确定」开始共享时 QQ 闪退，崩溃记录里是 `signal: 5 (SIGTRAP)` | 显示器坐标不从 0 开始时 QQ 算出空的窗口几何（#1）；本工具会自动处理，日志里应有 `empty-geometry fix: patched`，若是 `not patching` 说明 QQ 更新改了实现，请反馈 |
| KDE（KWin 6.7+）下开始共享时 QQ 闪退，日志里有 `explicit sync is used, but no buffer is attached` | 旧版边框隐藏与 KWin 的显式同步（`wp_linux_drm_syncobj_v1`）冲突；v0.2.10 起会把同步点中和成 `attach(NULL)`，升级即可 |
| 观看共享时画面花屏（横竖条纹） | Wayland + ANGLE 的 GLES `LUMINANCE` 模拟问题，见上文；启动器检测到 Vulkan 会自动规避 |
| 共享时仍出现全屏「屏幕共享」边框窗口 | 边框隐藏没生效：确认旧 QQ 已完全退出（含托盘）再从「QQ（Wayland修复版）」启动；正常时日志里有 `hiding 屏幕共享 border window`，没有就运行 `--doctor` 并反馈 |
| 「提示」麦克风通知条仍然弹出 | 提示条隐藏没生效：确认旧 QQ 已完全退出（含托盘）再从「QQ（Wayland修复版）」启动；正常时日志里有 `hiding QQ notification window (提示, …)`，没有就运行 `--doctor` 并反馈 |

### 单独关掉某个修复

排查时可以在启动前设置环境变量，单独关掉某一项：

| 环境变量 | 关掉的修复 |
| --- | --- |
| `QQ_WL_NATIVE_DISABLE=1` | 屏幕共享（包括共享电脑声音、共享时防闪退） |
| `QQ_WL_GEOMETRY_FIX_DISABLE=1` | 共享时防闪退 |
| `QQ_CLIPBOARD_FIX_DISABLE=1` | 剪贴板 |
| `QQ_CLIPBOARD_FIX_FORCE=1` | 强制启用剪贴板修复（KDE 上默认禁用，仅供测试） |
| `QQ_SCREENSHOT_FIX_DISABLE=1` | 截图 |
| `QQ_SCREENSHOT_KDE=0` | 只关 KDE 的 KWin ScreenShot2 截图路径 |
| `QQ_SCREENSHOT_PORTAL=0` | 只关 GNOME 的 portal 截图路径（默认仅 GNOME 会话启用） |
| `QQ_SCREENSHOT_PORTAL_TIMEOUT=300` | portal 截图等对话框的超时秒数（默认 60） |
| `QQ_BORDER_FIX_DISABLE=1` | 窗口修补（共享边框隐藏、截图覆盖层标题与全屏、提示条隐藏） |

例如：

```bash
QQ_CLIPBOARD_FIX_DISABLE=1 linuxqq-wayland-fix
```

渲染后端选项（不是关修复）：

| 环境变量 | 作用 |
| --- | --- |
| `QQ_WAYLAND_FIX_ANGLE=auto`（默认） | 检测到 Vulkan 时加 `--use-angle=vulkan`，否则不加 |
| `QQ_WAYLAND_FIX_ANGLE=swiftshader` | 强制软件 ANGLE，画面正常但较慢 |
| `QQ_WAYLAND_FIX_ANGLE=vulkan` / `off` | 强制指定 / 完全不加参数 |
